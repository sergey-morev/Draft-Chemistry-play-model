# Scientific review contract

Status: PROPOSED workflow. The owner reported an interested chemistry instructor associated with Universite de Moncton. Name, affiliation verification, exact commitments and articles are PENDING. No institutional endorsement is claimed.

## Roles

The owner decides project direction, access, funding and release. The instructor may review scientific content and help define curriculum; that role needs recorded scope and acceptance. Engineers implement and test; they cannot grant scientific acceptance to their own suggestions.

## First review questions

- Which course, learner level, language, learning objectives and assessment contexts?
- Which representations: Lewis, skeletal, ball-and-stick, stereochemical, coordination?
- Which initial compounds/reactions are appropriate and which features must be hidden?
- Is open-ended construction desirable, or should reviewed exercises bound the model?
- What counts as a chemically invalid, unsupported, unknown or merely approximate state?
- Which sources and data versions may be used, cited and redistributed?
- What instructor-visible evidence is required before a student pilot?

## Claim record

Each teaching claim needs: ID; precise statement; scope/phase/temperature/units where relevant; source URL/DOI and exact location; data/license provenance; implementation path and fixture; known exceptions; reviewer; review date; status; supersession pointer.

Statuses: PROPOSED -> EVIDENCE_ATTACHED -> REVIEW_REQUIRED -> SCIENTIFICALLY_ACCEPTED or REJECTED/REVISE. Only a recorded review decision establishes scientific acceptance; passing tests do not.

## Article intake

Store bibliographic metadata and links first. Upload a PDF only with confirmed permission/license. Record a relevant excerpt or original summary, not an invented citation. Do not import private correspondence or copyrighted papers into Git by default.

## Pilot gate

Use a small instructor-chosen set of compounds and transformations, with independently checked formulas, charges, structures, units and explanations. Freeze the exact commit and reviewed content manifest. Log remaining unsupported features. No student personal data or grades in the prototype.

No real-world experimental, nuclear, medical, or synthesis recommendations are required for this tool's learning goals.
